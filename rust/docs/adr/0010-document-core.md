# ADR 0010: Document core (RUST-06)

Status: accepted

## What the crate ports

- `ragmonk-documents` ports `documents/{normalizer,chunker,table_renderer,metadata,tokenization}.py`
  and `tokenization/{model_identity,model_tokenizer}.py`.
- The chunker consumes only the **canonical intermediate JSON**: a normalized
  document is a flat, index-addressed unit list (`title`, `page_count`,
  `is_scanned`, `units[]` with `kind`, `text`, `heading_level`,
  `heading_path`, `parent_index`, `page_start`/`page_end`, `table_rows`,
  `caption`, `header_row_count`).
  - No Python is involved after a normalized document exists.
  - Conversion that produces this format is RUST-07.

## Tokenizer

- **Library.** The Hugging Face `tokenizers` crate, pinned at `=0.23.2`, the
  same core the Python reference's binding wraps. It is built without the
  `onig` C dependency; the `fancy-regex` feature is enough for the BERT
  pipeline.
- **Assets.** The reference's bundled `all-MiniLM-L6-v2` assets (revision
  `1110a243…`) are compiled into the binary. They are verified against the
  same SHA-256 manifest before first use. The tokenizer never touches the
  network.
- **Identity.** The fingerprint and preprocessing identity strings are
  byte-identical to the reference. So is `chunker_version`
  (`2+tok:<revision>:<fingerprint>:max256`).

## Python string semantics reproduced

- `str.isspace` covers Unicode White_Space plus U+001C–U+001F.
  `strip()` and `split()` use the same definition.
- Sentence splitting reproduces `(?<=[.!?])\s+`; the Rust `regex` crate has no
  lookbehind, so it is implemented without one.
- Sub-word splits cut at the tokenizer's own offsets. They are byte offsets in
  Rust and char offsets in Python, but both point at the same boundaries.

## Parity evidence (`compat/golden/documents.json`)

The golden file is generated by `compat/tools/gen_document_golden.py` and
covers:

- Markdown, HTML and TXT fixtures, converted by the reference's Docling path,
  including Greek/CJK/emoji/RTL text, a 60-row table, a wide oversized cell
  and long headings.
- Synthetic documents: an oversized captioned table, an oversized single
  cell, a multi-row header, an empty table, very long title/breadcrumbs,
  Unicode paragraphs, and an empty document.

All of them were chunked under three configurations (default, small and
tiny), giving 30 document × configuration cases. The Rust output matches the
reference **exactly** for every case: every chunk field and every
diagnostics counter.

A 20-string Unicode corpus also matches exactly: token counts with and
without special tokens, sub-word splits, budget splits and sentence splits.

## Boundaries

- Every paragraph and table chunk's payload stays within
  `max_tokens - safety_tokens`.
- The documented exceptions are the same as the reference: headings are
  stored whole, and so is a single table-cell fragment that cannot be cut.
- Splits never cut inside a character.
- Oversized content (5k words plus a 20k-character word) chunks
  deterministically within the ceiling.

## Benchmark

All golden documents × configurations: Rust 0.28 s vs Python 0.49 s.
Tokenization dominates, and both use the same `tokenizers` core.
